# 协作规则

> 本文件定义本仓库的文档存放与 Git 变更管理规范，所有后续对话与修改均需遵守。

## 1. 文档存放规则

- 所有对话产出的文档（说明、方案、记录、总结等）统一放在仓库根目录的 `doc/` 文件夹下，不存放在其他位置。
- 文档命名使用简明的小写英文或中文主题名，扩展名默认为 `.md`；如需按主题归类，可在 `doc/` 下建立子文件夹。

## 2. Git 提交规则（批量周期提交）

**不要每次对话修改都自动提交。** 改为：每累计完成 **2 次** 包含代码、配置文件或文档修改的对话交互后，再统一执行一次 Git 提交与同步；用户显式要求提交时立即触发。

具体流程：

1. 平时对话期间（周期内第 1 次修改对话）：正常对代码、配置文件或文档进行新增、修改或删除，**不自动执行** `git commit` 与 `git push`。
2. 当累计达到第 2 次包含文件修改的对话交互时（或用户主动要求提交时），统一执行一次 Git 变更管理：
   - `git add .` 将所有变更暂存；
   - `git commit -m "<中文详细提交描述>"` 提交，描述必须**简明、专业、清晰的中文**，系统概括本轮累计修改的核心内容与变更点；
   - `git push` 同步到远程仓库（`origin`）；
   - 若没有远程分支或推送需要确认，向用户汇报当前 Git 状态，不擅自强推。
3. 提交完成后，重新开始计算下一轮 2 次对话修改周期。

## 3. Git 安全底线

- 远程仓库：`origin` → `https://github.com/wyxpro/opcalw.git`，遵循常规 Fast-forward 同步。
- 不强推（`--force`）、不跳过校验钩子（`--no-verify`）、不修改 Git 配置；`.env` 等敏感文件不得入库。
