## 二、单篇写作模板

```markdown
# 标题：动词开头，带一个可验证的结果
例：把 RAG 的 Recall@5 从 0.72 拉到 0.93，我只改了切片

## 0. 一句话结论（读者可以只看这段）
## 1. 场景：谁在什么时候会遇到这个问题
## 2. 直觉做法为什么会失败（给一个具体 badcase）
## 3. 我的做法（步骤 + 关键参数 + 代码块 ≤ 30 行）
## 4. 怎么验收（给出可算的指标，不写「效果不错」）
## 5. 边界：什么情况下别这么干
## 附：环境版本与复现命令
```

## 三、硬性规范（写完自查）

1. **标题不许诺没有的结果**：写了数字就必须有采集口径与复现步骤。
2. **代码块能直接跑**：给出版本号；依赖不超过 5 个；带一行 `# 期望输出`。
3. **至少一个失败案例**：只写成功经验的教程等于没写。
4. **指标优先于观点**：能算出来的不交给模型判断，也不交给感受判断。
5. **不堆名词**：出现一个新术语，必须在本篇内给出人话解释。
6. **每篇留一个钩子**：明确写出「这篇不能帮你解决什么」。
